# Публичный бот на Cloudflare Workers

Read-only Telegram-бот, который показывает статистику сканера кому угодно.
Личный бот (`main.py`) при этом не меняется: он остаётся на ноутбуке,
отвечает только владельцу и продолжает слать ему алерты.

## Как это устроено

```
ноутбук                      GitHub Pages              Cloudflare
меme-scout ──раз в час──▶ deftools.xyz/            ┌── worker
(SQLite)                   scout-stats.json ◀──────┤   читает снимок
                                                    └── отвечает в Telegram
```

У воркера **нет базы**. Он читает тот же снимок, который уже лежит на сайте,
поэтому ему не нужен ни включённый ноутбук, ни доступ к SQLite. Если ноутбук
выключен, бот честно скажет, что снимку столько-то часов, — но ответит.

Бесплатного тарифа Workers (100 000 запросов в сутки) хватает с огромным
запасом: один человек с одной командой — один запрос.

## Почему нужен ОТДЕЛЬНЫЙ бот

У одного токена не может быть одновременно webhook и long polling. Личный
бот работает через polling с ноутбука. Если повесить вебхук на его токен,
личный бот сломается. Поэтому для публичного нужен новый токен от BotFather.

## Команды

| Команда      | Что показывает                                  |
|--------------|-------------------------------------------------|
| `/start`     | что это такое и список команд                   |
| `/stats`     | воронка и разбивка по сетям                     |
| `/finds`     | последние токены, прошедшие проверки            |
| `/survivors` | кто пережил первые сутки с целой ликвидностью   |
| `/drains`    | у кого ликвидность упала больше чем вдвое       |

На любой другой текст бот молчит — чтобы не шуметь, если его добавят в группу.

## Проверка без деплоя

```
node test-local.mjs
```

Поднимает воркер локально, ходит за настоящими данными на сайт, а вместо
отправки в Telegram печатает, что бот ответил бы. Заодно проверяет, что
чужой секрет отвергается и что ответы влезают в лимит Telegram.

## Развёртывание

Нужны две вещи, которые может сделать только владелец аккаунтов.

**1. Создать нового бота.** В Telegram написать [@BotFather](https://t.me/BotFather)
команду `/newbot`, придумать имя и username. Он выдаст токен вида
`123456789:AA...`. Этот токен — пароль от бота, его нельзя коммитить.

**2. Войти в Cloudflare:**

```
npx wrangler login
```

Дальше уже механика:

```
npx wrangler secret put BOT_TOKEN        # вставить токен от BotFather
npx wrangler secret put WEBHOOK_SECRET   # любая длинная случайная строка
npx wrangler deploy
```

`deploy` напечатает адрес вида `https://meme-scout-bot.<аккаунт>.workers.dev`.
Последний шаг — сказать Telegram, куда слать сообщения:

```
curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -d "url=https://meme-scout-bot.<аккаунт>.workers.dev/webhook" \
  -d "secret_token=<ТОТ_ЖЕ_WEBHOOK_SECRET>"
```

Проверить, что всё сошлось:

```
curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

В ответе должен быть нужный `url` и `pending_update_count: 0`.

## Безопасность

- Секреты живут только в Cloudflare (`wrangler secret put`), в репозитории их нет.
- Каждый запрос от Telegram проверяется по заголовку
  `X-Telegram-Bot-Api-Secret-Token` — без него воркер отвечает 403.
- Бот только читает. Он не принимает адреса, ничего не записывает и не имеет
  доступа ни к базе, ни к кошелькам.
